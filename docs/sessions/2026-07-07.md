# 2026-07-07

## 14:00 — Campaign wizard redesign: shared target picker modal, centralized validation, visible type lock

**Scope/goal:** Redesign the advertiser campaign-creation wizard (`webapp/`) for a more professional,
consistent, responsive experience: replace the duplicated `SearchUser`/`SearchEvent` full pages with one
shared modal, add real per-step validation, prevent skipping ahead into an incomplete step, and make the
existing "campaign type is locked once created" rule visible in the UI instead of a silent omission.

**Changes made** (see full design in
[`docs/plans/2026-07-07-campaign-wizard-redesign.md`](../plans/2026-07-07-campaign-wizard-redesign.md) and
the task-by-task plan in
[`docs/plans/2026-07-07-campaign-wizard-redesign-plan.md`](../plans/2026-07-07-campaign-wizard-redesign-plan.md)):

- New `webapp/src/hooks/useCampaignWizard.ts` — typed `CampaignWizardData`, the single
  `getWizardData`/`saveWizardData`/`clearWizardData` API, `clearOtherTypeFields` (clears stale
  target/format data when the advertiser switches ad type mid-wizard), and a chain of completeness
  predicates (`isIdentityStepComplete` → `isTargetOrBrandStepComplete` → `isTypeCreativeStepComplete` →
  `isAdContentStepComplete` → `isTargetingStepComplete` → `isPaymentStepComplete`).
- New `webapp/src/components/campaign/TargetPickerModal.tsx` — replaces `SearchUser.tsx`/`SearchEvent.tsx`.
  Full-screen sheet on mobile (≤640px), centered dialog above that; enriched result rows (initials-fallback
  avatar for profiles, banner thumbnail for events); focus trap, Esc-to-close, click-outside-to-close.
- New `webapp/src/components/campaign/WizardStepGuard.tsx` — wraps every `/campaign/new/*` route (except the
  entry point) in `App.tsx`; redirects to `/campaign/new` if that step's prerequisites aren't met yet.
- `SelectAdType.tsx` now opens `TargetPickerModal` directly (no more separate search-page navigation) and
  shows the selected profile/event as a card with a "Change" action.
- New `webapp/src/components/ui/FieldError.tsx` and `AlertBanner.tsx` — one consistent look for field-level
  and submission-level errors, replacing three different ad-hoc error styles across `Payment.tsx`,
  `Review.tsx`, `EditCampaign.tsx`.
- Validation fixes: real URL check on `CreateAd`'s link field (previously accepted any non-empty string),
  `endDate > startDate` check on `Targeting`, explicit `budget >= 10` check on `Payment`, and a banner
  MIME-type check on `CreateAd`/`EditCampaign` (previously only checked file size, not type).
- `EditCampaign.tsx`: fixed a bug where a save failure (not just a load failure) replaced the entire edit
  form with the full-page error screen — now `error && !campaign` gates the full-page state, and a save
  error renders as an inline `AlertBanner` above the still-visible form. Added a read-only "Campaign type"
  badge with "To change the campaign type, create a new campaign." — the constraint was already enforced
  (no `adType`/target field exists in the edit form or its update payload), just not visible before.

**Key decisions & rationale:**
- No new test infrastructure. `CLAUDE.md` describes Vitest + Playwright for `webapp/`, but neither is
  actually installed (no `vitest` dependency, no test script, no `e2e/` folder) — a pre-existing gap
  unrelated to this change. Set up up a whole test framework was explicitly declined in favor of build +
  lint + manual verification, to keep scope on the actual UX request.
- Scoped the wizard-state migration narrowly: only `SelectAdType.tsx` and the new guard/modal use
  `useCampaignWizard`'s functions. The other step pages (`CreateAd`, `Targeting`, `AudienceTargeting`,
  `Payment`, `Review`, `BrandDetails`, `SelectBoostType`, `SelectAdFormat`, `UserAdPreview`,
  `EventPreview`) keep their existing local `localStorage.campaignWizard` helpers, which already worked
  correctly — rewriting them wasn't needed for the guard/modal to function and would have expanded the
  diff for no behavioral gain.
- Route guard redirects to `/campaign/new` (not to "the exact first incomplete step") on any failed
  predicate — simpler and unambiguous, at the cost of not resuming exactly where the advertiser left off.

**Verification:**
- `npm run build` (tsc -b + vite build) and `npm run lint` in `webapp/` — 0 new errors/warnings; the 11
  pre-existing lint problems (in files this change never touched) are unchanged before/after.
- Manual browser walkthrough (dev server + mocked `fetch` for auth/search, since no backend was running):
  confirmed the User Spotlight target picker opens, searches, selects, and closes; the modal renders as a
  full-screen sheet at 375px and a centered dialog at desktop width; the route guard redirects
  `/campaign/new/payment` back to `/campaign/new` when accessed directly without prior steps; the
  `Targeting` end-date error shows/clears correctly; the `Payment` minimum-budget error shows/clears
  correctly; the `EditCampaign` type-lock badge and copy render for a loaded campaign.

**Open follow-ups:** none required for this change. Optional future work (not requested): allow changing
the target profile/event — but not the ad type — on a draft/rejected campaign from the edit screen; add
real Vitest/Playwright coverage for the new hook and modal if the team decides to close the test-tooling
gap noted above.
