# Code & Design Review — `admin` & `webapp`

**Date:** 2026-06-16 · **Scope:** `admin/` and `webapp/` only (`legacy/` excluded). **Method:** three independent reviewer passes (admin code quality, webapp code quality, cross-app design/UX), each reading the full app source. Findings below are synthesized and de-duplicated.

## Verdicts at a glance

| App | Code quality | Design / UX | Production-ready? |
|-----|--------------|-------------|-------------------|
| **admin** | Solid, idiomatic architecture; one critical auth flaw + meaningful dead code | **Professional & clean ✓** | With fixes |
| **webapp** | Strong bones, but several critical correctness bugs in the wizard/auth/payment core; large dead surface | **Needs work** — half-finished token migration breaks rendering | **No** — fix correctness + tokens first |

## App independence — verified ✓

Mechanically confirmed the two apps are fully decoupled: no cross-imports either direction, no imports escaping either app's root, no root `package.json`/workspace, no symlinks, separate lockfiles. The divergence the reviewers note (tokens, HTTP client, UI primitives are forked copies) is **acceptable and intended** — the rule is independence, not sharing. Each app must simply be internally consistent.

---

## Priority action list (must-fix, ordered)

1. **webapp — card is charged before the campaign exists.** `Payment.tsx:102-151` runs `createPaymentIntent` + `confirmPayment` (a real charge) at the Payment step, but `campaignsApi.create` runs later in `Review.tsx:87-137`. If Review fails or is abandoned, the user is charged with no campaign. Capture payment atomically with creation (or defer the charge to final submit).
2. **webapp — email verification is a no-op.** `VerifyEmail.tsx:79-81` has the verify call commented out and always `navigate('/dashboard')`; any code "passes." Wire the real endpoint; navigate only on success.
3. **webapp — fake records leak into production search.** `SearchUser.tsx:42-72` / `SearchEvent.tsx:58-78` merge `HARDCODED_USERS`/`HARDCODED_EVENTS` into live results on every search; fabricated IDs become `spotlightUserId`/`eventId`. Remove the mock merge.
4. **webapp — targeting radius unit bug (miles → km).** UI selects miles (`Targeting.tsx:104`) but `mapCreateRequest` sends the raw number as `radiusKm` (`campaigns.ts:305`). Convert `* 1.60934` (or make the unit consistent end-to-end).
5. **webapp — uploaded banner image is dropped.** `CreateAd.tsx:61-67` stores only `hasBanner: boolean`; the `File` is never uploaded/persisted, so the banner feature is non-functional. Upload and store the resulting URL.
6. **webapp — ~19 undefined CSS tokens break rendering.** Names copied from admin (`--color-neutral-*`, `--color-primary-50..400`, etc.) are referenced but never defined in `webapp/src/styles/tokens.css`, including the core `Card` primitive typo (`--color-border-light` should be `--border-color-light`, `Card.module.css:12`) and a whole Dashboard modal (`Dashboard.module.css:750-857`). Result: invisible borders, wrong text colors, off-brand slate fallbacks. Define the tokens (or rename to `--color-gray-*`).
7. **admin — mid-session `401` forces logout instead of refresh-retry.** Refresh only runs once in `AuthContext.checkAuth` at mount (`AuthContext.tsx:20-36`); any later `401` dispatches `auth:session-expired` (`client.ts:41-44`), bouncing admins to login on normal token expiry. Implement one-shot refresh-and-retry in the client with a shared in-flight promise.
8. **both — `auth.refresh()` bypasses the shared client and skips CSRF.** `admin/src/api/auth.ts:43-52` and `webapp/src/api/auth.ts:50-59` use a raw `fetch` with no `x-csrf-token`; if the refresh route is CSRF-protected, reload-time refresh fails. Route through `apiClient`.

Everything below is the detail behind these and the lower-severity items.

## `admin` — back-office panel

### Code quality

**Strengths**
- Clean DTO/mapper boundary in every API module (`api/users.ts:29` `mapUser`, `api/campaigns.ts:36` `mapCampaign`, `api/pagination.ts:19` `mapPaginatedResponse`) — backend casing/null quirks normalized in one place.
- Centralized fetch wrapper with consistent 204/empty-body handling and a typed error guard (`api/client.ts:40-75`, `isApiError` at `:14`); CSRF token captured from headers and attached only to mutating methods (`:25-38`).
- Well-memoized hooks (`usePagination.ts:63`, `usePermissions.ts:8`); `Modal` memoizes its Escape handler and cleans up the listener + `body.overflow` (`Modal.tsx:23-42`); good list/key hygiene and indeterminate-checkbox handling in `Table.tsx:75-77`.

**Critical**
- **Mid-session 401 → forced logout** (`api/client.ts:41-44`). See priority #7.

**Important**
- **`Table` sort state is duplicated/uncontrolled** (`Table.tsx:33-34,87-104`): keeps local `localSortKey`/`localSortDirection` initialized once, while pages also pass controlled `sortKey`/`sortDirection` + `onSort` (`Users.tsx:267-268`, `Campaigns.tsx:336-337`). Two sources of truth desync on reset/clear. Make `Table` fully controlled.
- **Hooks depend on the `filters` object** (`useUsers.ts:44`, `useCampaigns.ts:44`): works only because callers memoize it; an inline `{}` from a future caller would loop. Depend on primitive fields instead.
- **`sendBulkEmail` hardcodes `success: true`** and never populates `errors` (`api/SendGrid_emails.ts:158-166`); a fully-failed send reports success. Derive `success` from `failedCount === 0`.
- **Division by zero on zero-budget campaigns** → `Infinity`/`NaN%` width (`Campaigns.tsx:145`, `CampaignDetail.tsx:138,143`). Guard `budget > 0`.
- **Duplicated, inconsistent currency formatting**: a shared `formatCurrency` exists but is unused, `Stripe_Payments.tsx:56-65` defines a cents-aware variant, and Users/Campaigns/export hand-roll `` `$${x.toLocaleString()}` ``. Consolidate on one utility with a clear cents-vs-dollars contract.
- **`auth.refresh()` skips CSRF** (`api/auth.ts:43-52`). See priority #8.

**Minor**
- `Input.tsx:15` uses deprecated `String.prototype.substr` and `Math.random()` for ids — prefer React 19 `useId()`.
- `Stripe_Payments.tsx` `fetchedRef` StrictMode workaround (`:34,108-112,184`) fights the framework; other pages don't need it.
- `types/index.ts:2,26` — `[key: string]: unknown` index signature on `User`/`Campaign` weakens type safety; relax the `Table` constraint instead (e.g. `keyField: keyof T`).
- Magic numbers/strings: debounce `300` (`useUsers.ts:17`, `useCampaigns.ts:17`), skeleton rows `5` (`Table.tsx:113`), toast `5000` (`ToastContext.tsx:32`), inline pagination padding (`Users.tsx:274`, `Campaigns.tsx:343`).
- Vendor-prefixed snake_case filenames (`SendGrid_emails.ts`, `Stripe_Payments.tsx`) are inconsistent with the PascalCase/camelCase used everywhere else and leak the vendor into route-level page names.

**Dead / unnecessary code**
- `utils/formatters.ts` — **entire file unused** (all 5 exports, zero references).
- `hooks/usePermissions.ts` — unused; and with it, `utils/permissions.ts` becomes dead (`canAccessSettings`, `canManageUsers`, `canApproveCampaigns`, `ROLE_PERMISSIONS`, `PERMISSIONS` have no external callers; `AuthContext` has its own independent `hasPermission`).
- `types/index.ts:79-84` `ApiResponse` — unused. `api/SendGrid_emails.ts:7-10` `EmailRecipient` — unused; `BulkEmailResult.errors` declared but never populated.
- Duplicated `buildQueryString` (`users.ts:63`, `campaigns.ts:77`) + `buildQuery` variant (`Stripe_payments.ts:161`) → extract a shared helper.
- Placeholder/stub UI shipping as real: "coming soon" in `UserDetail.tsx:140` and `CampaignDetail.tsx:162`; `dashboard.ts:31` hardcodes `recentActivity: []` and growth metrics to `0`; danger-zone actions in `Settings.tsx:60-76` only fire toasts (no API), making the surrounding `try/catch` dead.
- No commented-out blocks; no unused npm dependencies.

### Design — Verdict: **Professional & clean ✓**

**Strengths:** complete token system with **zero undefined references**; consistent primitives (`Button` 5 variants × 3 sizes with disabled/loading; `Input.tsx:20` ties `label htmlFor` to a generated id; designed empty + skeleton/shimmer states in `Table`); good responsive grids (`Dashboard.module.css:30-40`, `Settings.module.css:32-51`); semantic shell (`Sidebar` uses `aside/nav/ul`, `aria-label` on icon buttons), global `:focus-visible`.

**Issues**
- *Important:* no z-index token scale, yet z-index is hardcoded (`Modal.module.css:8`, `Toast.module.css:5`, `Sidebar.module.css:11`, `AdminHeader.module.css:13,73`) — add `--z-*` tokens. Settings toggle switch has unlabeled `span`s and no `:focus-visible` on the slider, so keyboard focus is invisible (`Settings.module.css:151-196`, `Settings.tsx:204-208`). `AdminHeader.tsx:71` `.userMenu` is a clickable-styled `div` with no `role`/`tabIndex`/handler.
- *Minor:* two parallel token vocabularies coexist (`--space-*`/`--text-*` vs `--spacing-*`/`--font-size-*` aliases) — standardize on one. Hardcoded hex bypassing tokens (`Button.module.css:62`, `Badge.module.css:34`, `Dashboard.module.css:75`). `Input.tsx` lacks `aria-invalid`/`aria-describedby`/`role="alert"` (webapp's Input has these).

## `webapp` — advertiser app

### Code quality

**Strengths**
- Clean api/ mapping layer with defensive coercion (`campaigns.ts:221-262`, `user.ts`, `Stripe_payments.ts`).
- Strong type safety — `any` effectively absent from `src/` (only in an e2e helper); unknown errors via `isApiError` guard (`client.ts:11-18`).
- `CityAutocomplete.tsx` is a model component: full keyboard a11y (`role="combobox"`, `aria-activedescendant`, arrow/Enter/Escape), click-outside cleanup (`:128-140`), memoized filtering.
- `LocationMap.tsx` handles async geocoding correctly: `AbortController` (`:48-51`), debounce cleanup (`:91-97`), ignores `AbortError` (`:76`). `CreateAd.tsx:46-55` creates and revokes the preview object URL (no blob leak).

**Critical**
- Payment charged before campaign exists (`Payment.tsx:102-151` vs `Review.tsx:87-137`) — priority #1.
- Email verification no-op (`VerifyEmail.tsx:79-81`) — priority #2.
- Hardcoded fake users/events in search (`SearchUser.tsx:42-72`, `SearchEvent.tsx:58-78`) — priority #3.
- Radius miles/km bug (`Targeting.tsx` + `campaigns.ts:305`) — priority #4.
- Uploaded banner image dropped (`CreateAd.tsx:61-67`) — priority #5.

**Important**
- **Refresh path bypasses client CSRF** (`AuthContext.tsx:22-42` + `auth.ts:50-59`): on load, `getProfile()` runs before `setClientAuthenticated(true)`, so the client's 401→refresh→retry (`client.ts:64-77`) is skipped; the fallback `authApi.refresh()` is a raw `fetch` with no CSRF header — duplicates logic that already exists (with CSRF) in `client.ts:43-62`. Consolidate. (Priority #8.)
- **Refresh-retry race** (`client.ts:43-44`): a concurrent second `401` returns `false` instead of awaiting the in-flight refresh, so parallel requests (`Dashboard.tsx:134-137`) can spuriously log the user out. Queue behind a single shared promise.
- **Dashboard impressions/clicks/CTR are permanently zero** (`Dashboard.tsx:139-140`): double-casts to read `impressions`/`clicks` that `mapCampaignSummary` drops (`campaigns.ts:221-234`). Add the fields to the mapper or remove the dead computation.
- **`useForm.isValid` is misleading** (`useForm.ts:136`): derived only from `errors`, which is empty until blur/submit, so an untouched empty form reports valid. (Moot — `useForm` is unused — but a trap if revived.)
- **Wizard step numbering is wrong** (`WizardLayout.tsx`): every step passes `totalSteps={3}` though the real flow is 5-7 screens. Derive from a single flow definition.
- **`${budget}.00` breaks for decimals** (`Payment.tsx:313`): a `100.5` budget renders "$100.5.00". Use `parseFloat(budget).toFixed(2)`.

**Minor**
- `AuthContext` `value` not memoized (`:78-91`) — re-renders all consumers. `SendGrid_emails.ts:45-103` omits the `/v1` prefix used everywhere else (two live calls likely hit wrong paths). Wizard `localStorage.setItem` writes are unguarded against quota/serialization errors. `playwright.config.ts:4` comment says "Admin" (wrong app). `data/texas-cities.ts` — autocomplete is Texas-only but presented as general. Repeated literals: wizard key `'campaignWizard'`, `0.05` service fee, cents conversion.

**Dead / unnecessary code**
- `hooks/useForm.ts` — **entirely unused** (only its own barrel export).
- `utils/validation.ts` — **almost entirely dead**: every rule/formatter is unused except `validate()`, consumed only by the dead `useForm`. (137 of ~206 unit tests exercise this dead module.)
- `components/ui/Card.tsx` (+ CSS) — exported but never imported. `components/ui/Skeleton.tsx` — all 5 exports unused.
- Large unused API surface: `Stripe_payments.ts` (`getTransactions`, `getTransaction`, `getInvoices`, `getInvoice`, `downloadInvoice`, `requestInvoiceEmail` + their re-exported types); `SendGrid_emails.ts` (`getEmailPreferences`, `updateEmailPreferences`, `contactSupport`, `subscribeNewsletter`, `unsubscribeNewsletter`, `requestCampaignReport`, `requestInvoiceEmail` + types); `campaigns.getStatistics`; `user.deleteAccount`.
- `types/api.ts`: `ApiResponse`, `PaginatedResponse`, `LoginResponse` unused; `EmailPreferences` duplicated here and in `SendGrid_emails.ts:13`.
- `saveWizardData`/`getWizardData` copy-pasted across 12 wizard files + a variant in `Review.tsx:18-25` → extract a single `wizardStorage` util.
- `@` path alias in `vitest.config.ts:37-40` not mirrored in `vite.config.ts`; `@/` used in zero files — dead config.
- `mapUserFromBackend` (`auth.ts:15-28`) re-copies fields already produced by `mapProfileResponse` — redundant. `HARDCODED_USERS`/`HARDCODED_EVENTS` leftover placeholder data. `test/setup.ts:43` one commented-out line.

### Test assessment — weak and partly misleading
- **Unit tests** cover only `Button`, `Input`, and `validation` — but `validation.ts` is dead, so most assertions test code no user runs. Zero tests for the risky logic: `apiClient` (CSRF/refresh-retry), `AuthContext`, the mappers, the radius conversion, or any wizard page.
- **E2E specs are broken**: `campaign/dashboard/settings` specs navigate to routes that don't exist in `App.tsx` (`/campaign/select-ad-type`, `/campaign/edit/1` vs the real `/campaign/new/*`, `/campaign/:id/edit`); the `login` helper hits a real backend on `:3000` that `webServer` never starts (auth `beforeEach` will time out); most assertions are wrapped in `if (await x.isVisible())` so they pass vacuously.
- **80% coverage thresholds** (`vitest.config.ts:25-32`) are unrealistic and would fail on a real run — coverage is concentrated on a small dead module while ~all pages, hooks, context, and the api client are untested.

### Design — Verdict: **Needs work**

**Strengths:** the most thorough responsive design in the repo (`Header.module.css` full mobile menu, `Dashboard.module.css` four breakpoints + horizontal-scroll table fallback, `LandingPage` hero reflow); best-in-repo accessible primitives (`Input.tsx:34-43` `aria-invalid`/`aria-describedby`/`role="alert"`; `SelectionCard.tsx:35-42` `role="button"`+`tabIndex`+Enter/Space+`:focus-visible`); all 21 `<img>` have alt text; `.sr-only` utility exists.

**Issues**
- *Critical:* ~19 undefined tokens, core `Card` border typo, Dashboard-modal block (and recurrences across `EventPreview`, `SearchEvent/SearchUser`, `AudienceTargeting`, `UserAdPreview`, `BrandDetails.module.css:39`, `CityAutocomplete.module.css`) — priority #6.
- *Important:* off-brand fallback palette — `StripeSuccess.module.css:6,36,49,52,59` falls back to Tailwind **slate**, not the app's **teal**. Hardcoded status hex in shared `Badge.module.css` (`#b89600`, `#e3f2fd`, `#fce4ec`, `#c62828`) and others. Inline-style placeholders that read as unfinished: `Review.tsx:215` `color: 'red'`, `EditCampaign.tsx:153`, `LocationMap.tsx:103-119` raw hex states. `Auth.module.css` code/date inputs define `:focus` but no `:focus-visible` ring.
- *Minor:* `tokens.css:46` `--color-info-light` is darker than `--color-info` (inverted). `BrandDetails.module.css:39` `.label` uses a broken token while the shared `Input` label works → inconsistent colors on one step. Hardcoded focus-ring rgba in `Input.module.css:44,82`.

## Cross-cutting notes

- Both apps were forked from a shared base. **admin completed its token system (and back-filled aliases so everything resolves); webapp did not** — it inherited admin-only token names without defining them. This is the single highest-leverage design fix for webapp.
- Tokenize status/warning colors in both apps (both hardcode `#b8860b`/`#b89600` for warning text).
- Accessibility is uneven *within* each app: webapp's `Input` is the gold standard but its card-click and code-input focus states regress; admin's aria coverage is good but its `Input`, Settings toggle, and header user-menu need the same treatment. Each app should promote its own best primitive to a template.
- Neither app implements light/dark theming (admin has the semantic-alias foundation for it; webapp has no semantic layer). Not required, but noted against the earlier admin docs that claimed a theme toggle.

## Suggested sequencing

1. **webapp correctness** (priorities #1-#5) — these are user-facing/financial bugs; pair each with a real unit/e2e test.
2. **webapp tokens** (#6) — restores correct rendering; cheap, high-impact.
3. **auth hardening** (#7-#8) — admin refresh-retry + CSRF on both apps' refresh.
4. **Dead-code sweep** — remove the unused `utils`/hooks/components/API surface in both apps (large, low-risk; satisfies the "no dead code" rule). Re-run `tsc -b` after.
5. **Fix or quarantine webapp e2e** and recalibrate coverage thresholds to reality.
6. **Design polish** — z-index tokens (admin), tokenize status hex, unify focus-visible, replace inline-style placeholders.
